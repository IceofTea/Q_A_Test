# 内核直接插件标准（草案 v0.1 · 2026-10-19）

***

直接插件 = **可直接被内核装载使用的插件**，不经过外围宿主中转。按 AnYuanHost 10-18 要求，由三件套组成：**意向性知识库 + DLL 动态链接库 + 符号表**。本文规定三件套的契约与内核导入流程；开发决策流程见 skill `kernel-direct-plugin-development`。

> 边界：内核本体为预编译 `.lib`，本标准只定义**插件侧必须满足的契约**；内核装载机制的实现归 AnYuanHost。

## 一、三件套契约

### 1. 意向性知识库（`*.kb` 目录）

插件自带的、可供内核导入的知识，两部分：

| 组成 | 内容 | 参照 |
|---|---|---|
| 字典 | 本插件专属名词/质性 → 超索引条目的映射表（txt，格式对齐 `KRS\Data` 字典） | `Doc/MD/Lib_Introduce/Intentionality-Project/` |
| 意向性对象存储文件 | 按 `FstreamWriteIntentionalityObject` 系列格式序列化的对象文件——质性（指向信息的意向）+ 质料（信息实体） | `Fstream*Intentionality*.md` 系列 |

导入后对象经 `AddIntentionalityObject`（SuperIndexSet 域）登记，由总元素环境检索器（EES）按超索引直达——**插件不得自建注册表**。

### 2. DLL 动态链接库（`*.dll`）

- 导出**公共接口面**：本插件对外提供的元素构造、集合判定、映射函数的 C 符号（`extern "C"` 统一 ABI，避免 C++ 名字修饰差异）。
- 接口按 ESM 三元组织：`NewXxx`（构造）、`ReleaseXxx`（释放，配对）、`GetXxx/PutXxx`（存取）、`XxxSetTest`（集合判定）、`XxxFunction`（映射函数体）。命名与实现纪律遵循 `map-library-development-standard`。
- 生命周期契约：`Init/Shutdown` 入口；谁分配谁释放；`Read` 类接口返回的引用在 `Add/Remove/Put/Release` 后失效（意向性对象纪律）。

### 3. 符号表（`*.sym` 或内嵌导出段）

内核按符号表从 DLL 解析出 **元素 / 映射 / 集合** 的可用清单。表项（建议文本行格式，与 .pi 风格一致）：

```
条目类别  导出名        内核语义名        定义域集合     值域集合      备注
Map      CMDPutString  CMDPutString     StreamSet     NullElementSet
Set      QACMDSetTest  QACMDSet         -             -
Element  QACMDVersion  QACMDVersionInfo -             -
```

- `条目类别 ∈ {Element, Set, Map}`：决定内核把它注册进哪个检索域。
- `导出名` = DLL 导出符号；`内核语义名` = 脚本节点/.lan 中使用的检索名（二者一致可省略备注）。
- Map 条目必须给出定义域/值域集合名，供内核做节点归属判定；集合名须指向符号表中或内核已有的 Set。

## 二、内核导入流程（契约顺序）

```
装载 .kb 字典 → 注册插件专属质性到 EES
      ↓
读 .kb 对象文件 → 逐对象 AddIntentionalityObject 登记（意向性行为挂接）
      ↓
LoadLibrary(DLL) → 调用插件 Init（可用宿主侧只读句柄）
      ↓
读符号表 → GetProcAddress 逐条解析 → Element/Set/Map 注册进公共检索域
      ↓
脚本层即可按语义名引用插件映射（.lan 节点四段式照旧）
```

卸载逆序：先解注册符号表条目 → 插件 Shutdown → ReleaseLibrary → 意向性对象 `Remove/Release` 收尾。

## 三、CMD 复刻实战的缺口分析（本标准第一批用例）

脚本复刻 `buf.obj`（`KRS\Data\KRS_Solution\SolutionCmdReplica.lan`）所需映射 vs 现有覆盖：

| 需求 | 状态 | 说明 |
|---|---|---|
| 固定串输出 hello world | ✅ 已有 `CMDPutHelloWorld`（Fast_CMD.lib） | 可作插件映射的参照实现 |
| 按参数字符串输出 | ⬜ 缺口 → `CMDPutString` | 定义域 StreamSet，值域 NullElementSet |
| 毫秒级阻塞等待 | ⬜ 缺口 → `CMDSleep` | 定义域 UIntSet（毫秒数），值域 NullElementSet |
| 输出缓冲 flush | ⬜ 缺口 → `CMDFlushOutput` | 定义域 NullElement，值域 NullElementSet |

三个缺口映射即 `qacmd_plugin`（示例直接插件）的接口面；其状态/配置等登记信息走意向性对象，不自建存储。

## 四、与 `app/cpp/plugin` 现有体系的关系

现有 `qaplugin.hpp`（IPlugin/HostApi/CommandDef + LoadLibrary 宿主）是**生态侧宿主插件**——经 HTTP 桥供工作区调用，内核不认识它。直接插件是**内核侧插件**——符号表 + 意向性知识库直接被内核装载进映射检索域。两者并存演进：生态插件原型验证后，按本标准补齐三件套即可"升格"为直接插件；`Init/Shutdown/命令路由`设计经验复用，差异仅在注册目标（内核 EES/映射域 vs 宿主 CommandDef 表）。
