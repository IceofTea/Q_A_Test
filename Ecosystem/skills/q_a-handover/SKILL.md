# Q_A_Test 接力开发交接技能

本项目采用**接力式开发**：不限定一个人、一台机器、一个环境，任何人（或 AI 会话）在任何环境接手都能继续推进。这个技能就是接力棒——核心原则是：**先读台账恢复上下文，干完活立刻写回台账**。

> **项目定位**：本项目为"庞杂系统"（Q_A_Test）内核及其生态。内核设计思想参考了一份**外部技术资料**（存于 `参考资料\`，仅内部参考、不随交付分发）。术语（ESM / 总元素环境检索器 / 零轮询机 / 解决方案 / 意向性）与代码模块、数据层的对照见《项目手册.md》第〇章；接手前先看它，能省很多时间。

## 为什么这样设计

- 开发分散在多台机器（个人电脑、学校实验室电脑）、多人（AnYuanHost 管内核，我方管前后端）之间切换；
- AI 会话之间没有共享记忆，不主动写盘就会丢失进度；
- 需求是陆续冒出来的（"想起来啥新需求写进去"），不实时记录就会漏。

## 第一步：恢复上下文（接手时必做，按顺序读）

1. 读 `项目手册.md` —— **唯一的内部全量文档**：项目分析、协作背景、环境与运行、进度看板、问题台账、自检报告。**这是交接的主文档。**
2. 读 `对接说明.md` —— 给 AnYuanHost 的对外短版，了解与对方的对接状态与待办。
3. **核对实际状态**：台账可能滞后于磁盘，用文件列表、git log、构建产物时间戳验证看板上的"进行中/受阻"是否仍然属实，不符就先修正台账再干活。
4. 如果要动具体模块，再按需读 `Q_A_Test-master\Doc\MD\MainMarkDown.md`（官方文档入口）和 `Lib_Introduce\Q_A_Lib_Introduce.md`（静态库 API 手册）。

## 第二步：干活

按"下一步行动"的优先级推进。约定：

- **前后端开发**是本方职责，基于 AI agent（当前主力为 Devin CLI，历史使用过 opencode）进行；内核本体、内核↔后端接口、插件装载机制归 AnYuanHost，遇到依赖他接口的活，先标记为"阻塞（对方侧）"，不要空等，转做不依赖接口的部分（页面、静态展示、接口 mock）。
- 展示版与落地版是同一套代码的演进关系，不做一次性 demo：接口层保持可替换，方便他的插件接口就绪后直接挂接。
- 动了 `Q_A_Test-master` 里的东西，注意内核是预编译静态库，改不了内核本体，只能改 `h.cpp\`、`Execute\` 等源码与前端新增代码。

## 第三步：写回台账（每次工作结束前必做）

更新 `项目手册.md`，规则：

1. **状态看板**（第四章）：完成的改 ✅，开始的改 🔄，新发现的加行，受阻的写清原因；
2. **问题台账**（第五章）：新问题按 `ISS-nn` 追加到总览表并按同款模板补详情；
3. **进度日志**（第六章）：在表格**顶部**追加一行（倒序），格式 `| 日期 | 记录 |`，一句话写清做了什么、结果如何、留下了什么；
4. **下一步行动**：按最新情况重排优先级；
5. **新需求**：随时追加到"有效需求清单"或看板，注明来源（如"对方 10-15 提出"）；
6. 最后更新文档头部的"最后更新"日期。
