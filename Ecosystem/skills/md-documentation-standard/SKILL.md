# 文档编写标准

本 skill 规定库开发文档的组织方式与单篇写法，目标是让每个 Element、Set、Map 的具体信息都可被独立检索、可被智能体直接引用。模板来源：`E_S_M-Project/`。

## 0. ESM 设计模式贯穿（生成文档时的建模依据）

库按「元素-集合-映射」三元模式组织（详见「库映射开发标准」skill：`map-library-development-standard`），文档必须同样按三元模式成套产出：

- **一种数据类型 = 一套文档**：集合文档（`XxxSet.md`，判定规则）+ 构造映射文档（`NewXxx.md`）+ 释放映射文档（`ReleaseXxx.md` 或引用通用 `ReleaseElement`）+ 操作映射文档（`GetXxx`/`PutXxx`/计算类）+ 解析宏文档（若有 `GetXxx` 宏）。缺任何一篇都视为文档不完整。
- **文档要体现三元关系**：集合文档写明「哪些映射以此集合为定义域/值域」；映射文档写明「定义域/值域属于哪个集合、可通过哪个宏解析」；宏文档写明「服务于哪个集合」。三者互链成闭环。
- **代码层 ↔ 内核层等价对**：凡是封装了操作符/宏的映射（如 `QuoteElement` 封装 `|=`、`PutPairFirstElement` 封装 `GetEleOrder(...)&=`），映射文档必须写出其等价的代码写法，并注明「代码中可用操作符，虚拟机中只能用该映射」——这是 ESM 模式「操作即映射」的核心表达。
- **复合对象写明元素序列布局**：按元素序列/元素树设计的对象，其集合/构造文档必须列出槽位表（下标 → 含义 → 子元素类型），使 `GetEleOrder` 可被逐槽位解读。

## 1. 目录架构（四级结构）

```text
项目根/
├── 项目名.md                     # 项目索引：职责 + 源文件清单
├── 模块A/
│   ├── 模块A.md                  # 模块索引：分类 + 实体链接
│   ├── 实体名.md                 # 一个 Element/Set/Map/宏/异常码 一篇
│   └── 主题_Case.md              # 案例文档：跨实体的综合演示
└── 模块B/
    └── ...
```

规则：

1. **一个实体一个文件**，文件名 = 实体名（`UIntAdd.md`、`UIntSet.md`、`GetEleOrder.md`），大小写与实体一致。
2. **每层都有索引 md**：项目索引列出模块；模块索引列出实体并**分类分组**。
3. **案例单独成文**，命名以 `_Case.md` 结尾（如 `Element_Advance_Case.md`），挂在所属模块索引的「案例」小节下。
4. 新增/删除实体必须**同步更新上级索引**，否则视为未完成。

## 2. 通用版式

```markdown
# 实体名

***

一句话定义句（含定义域/值域集合、或结构/类型）。

```C++
定义代码（可直接抄录使用）
```

功能语义段：中文全称（英文名）做什么、为什么需要它。

***

## 案例：

```C++
可运行的最小案例
```

案例解释段：逐句说明做了什么，指出等价关系与风险（释放、引用、失效）。
```

版式约定：

- `#` 一级标题 = 实体名，与文件名、代码符号三者一致。
- 用独立一行 `***` 分隔大段落，全篇保持节奏统一。
- 代码块一律用 ` ```C++ ` 围栏；定义行、宏定义、案例分开成块，不混写。
- 相关实体用相对路径互链：`[ExceptionSuccessTest](ExceptionSuccessTest.md)`。
- 正文为中文，先给定义、再给语义、最后给案例；不写空泛形容词。

## 3. 各类文档模板

### 3.1 映射文档（Map）

必含要素（顺序固定）：

1. 标题 `# 映射名`
2. 定义句：「映射 X 接受〈定义域集合〉为定义域，〈值域集合〉为值域，定义如下：」——集合名附中文释义（如「元素序偶集合（OrderedPairSet）」）
3. 定义代码块：`Map X(&DomainSet, &RangeSet, XFunction);`
4. 功能段：中文全称 + 缩写 + 输入格式约定（如「序偶格式为<UIntSet, UIntSet>」）+ 输出行为
5. 若封装了代码层操作符/宏，写明**等价代码写法**并注明「代码可用操作符，虚拟机中只能用该映射」
6. 使用规范/限制（值域与定义域重合、适用结构类型、异常抛出等）；无则省略
7. `## 案例：` 代码块 + 解释段；若案例冗长，改为互链「案例参考映射 [X](X.md) 的案例」

### 3.2 集合文档（Set）

1. 标题 + 定义句（集合覆盖哪些元素、判定规则）
2. 定义代码块：`Set UIntSet(EmptyElement, UIntSetTest);`
3. 用途段：在框架中的作用、支撑哪些常见操作
4. 关联互链：解析宏（如「通过宏 GetUIntElement 解析」）+ 以该集合为定义域/值域的代表性映射（相对路径链接）
5. 复合集合（序偶/序列/树）附**槽位布局表**：下标 → 含义 → 子元素集合
6. `## 案例：` 展示构造 → 判定 → 操作的完整链

### 3.3 结构体文档（Element/Set/Map 本体）

1. 标题 + 「作为本框架的〈定位〉」+ 完整 `struct` 定义块
2. 逐成员/逐函数的小节：`## 名称` → 签名代码块 → 语义说明 → 示例
3. 风险单独成节并给出规避写法（如 Element 的「重复释放导致的异常」「不完全引用导致的引用失效」，各配反例代码）
4. 析构/释放策略必须写明（简单结构、复杂结构、引用元素三类处理）

### 3.4 宏文档（GetEleOrder 等）

1. 标题 + `#define` 定义块
2. 用途一句话（是否允许嵌套）
3. `## 案例：` + 内存管理提示（宏不触发自动析构，需手动释放）

### 3.5 案例文档（*_Case.md）

1. 标题（中文主题）+ 引入段（本例覆盖哪些映射、演示什么）
2. 按主题分 `##` 小节；每小节：说明段 → 代码块 → 等价代码对比（`与上面等价的写法`）→ 注意事项
3. 结尾回到内存/引用纪律，指出易错点

### 3.6 索引文档

- 项目索引：`# 项目名` → 职责段 → `## 源文件：` 链接列表 → 使用方式段（引入哪个头文件、打包形式）
- 模块索引：`# 模块名` → 职责段 → 按功能分类的 `## 分类：` 链接列表 → `## 案例：` 列表

## 4. 内容质量清单

- [ ] 标题、文件名、代码符号一致
- [ ] 映射文档写明**定义域与值域**的集合名（中英对照），与代码中 `Map` 定义行一致
- [ ] 一种数据类型的文档成套（Set + New + Release + 操作 + 宏），集合↔映射↔宏三向互链闭环
- [ ] 封装操作符/宏的映射写明等价代码写法与虚拟机限制
- [ ] 案例可直接抄录编译，解释段说明「做了什么 / 等价什么 / 风险在哪」
- [ ] 构造与释放成对出现；引用有 `ZeroElement` 解除步骤
- [ ] 代码符号拼写与真实库一致（如 `PutPairSecoundElement` 的历史拼写不要擅自更名）
- [ ] 上级索引已更新，交叉链接路径正确（相对路径）
- [ ] 新增异常码在 `Exception/ExceptionCode/` 有独立文档并入索引

## 5. 新增/修改流程

1. 写实体 md（按第 3 节对应模板）
2. 若是新分类，先在模块索引里建 `## 分类：`
3. 更新模块索引链接；若新增模块，更新项目索引
4. 需要演示时补 `_Case.md`，并在模块索引「案例」下挂链
5. 用第 4 节清单自检一遍
